# Incident-day exercise plausibility, version 1

This is a development-only audit of consistency with declared exercise rules. The bounds in `bounds-v1.json` are assumptions for screening, not operational requirements, law, empirical calibration, or physical validation. At 500 m resolution, one cell per minute corresponds to 30 km/h; the 5 km/h radial-activation screen is an explicitly invented threshold, not a measured maximum fire speed. The calculated rate uses distance from the initial footprint divided by elapsed time; coarse cell activation does not establish front speed.

Reported burned hectares multiply occupied grid cells by cell area. They are a coarse grid-footprint proxy, not a measured burned area or perimeter, and must not be presented as such.

Run from the repository root with a new output directory:

```sh
python eval/check_incident_day_plausibility.py --output /tmp/my-plausibility --wall-budget 180 --cases incident-day-shift-v1-001 incident-day-shift-v1-005
```

Omit `--cases` to request all six shift days, or provide `--cases` with no IDs for shift static checks only. Explicit old development IDs remain supported, and each selected suite receives six static checks. `--inputs` and `--network` accept a matched pair of existing, hash-pinned incident-day JSON packs; `--allow-unapproved-data` explicitly permits unapproved exercise inputs and never approves them. `--land-mask` accepts an existing, grid-aligned JSON matrix with 1 for land, 0 for water and null for unresolved classification. The mask is a supplied assumption: its source, alignment, water classification and fitness require independent review. The checker never fetches data. No land mask means sea exclusion is unknown; unresolved cells stay unknown.

All six scenarios receive static checks first, including model-based handover work reach and initial road options. Dynamic runs use one CPU worker at a time and the public dispatcher, preserve compressed minute audits, communications, orders, offered routes and trajectories in the fresh output directory, and report censoring on budget exhaustion. Each completed case must pass exact replay and independent reward verification, with all three verification flags recorded. The default wall budget is 600 seconds. The budget includes static work; static checks are always completed, so very small budgets can be exceeded by static overhead. Output is private exercise data, not historical evidence.

Movement checks bound straight-line displacement using declared speeds; path checks compare offered road legs to their stated edge speeds and lengths. Neither proves that all dispatched and return journeys were reachable or that roads were safe. Handover setup happened before minute zero, so its duration is unknown. The current minute audit does not record clearance or journey plans; daylight/wind checks screen recorded aircraft work, not full aviation authorization. Delayed communications and protection order timestamps are checked when recorded. Static counterfactuals separately compare modeled safety and candidate routes under wind and access changes, aircraft availability, destination capacity/closure and predeclared shortages. They do not require the policy to incur harmful outcomes and do not prove actual event causation.

Automated exercise consistency passes only after six completed, verified days, no contradictions or compilation blockers, a stable implementation and demonstrated counterfactual mechanics for every case. Human review remains pending independently. Physical validation remains separate and is not established by passing exercise checks, deterministic replay, or high baseline scores. Fuel, weather, spread, resource performance, aviation, duty, exposure and geography require independent evidence for claims about the real world.

The preserved legacy development cases place engine-0 four cells from its nearest eligible burning cell while the modeled reach is three. New `incident-day-shift-v1-*` cases instead select reachable, useful staging with a legal return. If the cached real road graph cannot support that staging, the handover explicitly carries a mapped synthetic failed-access recovery journey; it does not invent access or ground suppression. Unsuccessful work preserves water and work inventory and requests reassignment. Wind/access and shortage mechanics are checked by explicit counterfactuals without requiring a competent policy to incur harm.

The new bounded profile uses three eight-hour ground waves and two daylight-gated aircraft slots. Every slot is declared in the initial finite roster. Dispatch reserves return time, and active units begin recovery before the declared shift end when a route exists. If modeled egress becomes unavailable, the unit reports that once per unavailable period, remains visibly in assistance, and may recover late when access returns. The audit distinguishes this documented exception from unexplained overtime; it does not certify the route as safe. Eight hours is an exercise assumption, not duty law. The old scenario and profile identifiers remain available.
